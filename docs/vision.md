# Epoch: что строим и зачем

Epoch — платформа, где инженер учится, соревнуется и доказывает уровень. Здесь можно решать олимпиадные задачи, писать контесты, сдавать задания в формате ШАД, проходить курсы с домашками через git push, играть CTF и ML-соревнования. Всё это попадает в один профиль и один рейтинг.

## Две цели

1. **Учебный полигон — главная цель.** Каждая веха — настоящая инженерная задача, после которой разбираешься в новой области. Песочница учит Linux изнутри, judge — очередям и базам, контесты — событийной архитектуре, прод — Kubernetes и SRE. Карта знаний — в [learning-map.md](learning-map.md).
2. **Возможный сервис.** Если платформой начнут пользоваться кружки, вузы или компании, архитектура не должна мешать сделать из неё сервис с организациями и SLA. Биллинг, тарифы и продажи появятся только вместе с живыми пользователями.

## Для кого, если проект станет сервисом

| Кто | Что получает |
| --- | --- |
| Студенты и джуны | Задачи, задания как в ШАД, рейтинг, портфолио |
| Олимпиадники, CTF-игроки, ML-щики | Контесты, CTF, ML-соревнования, сезонные лиги |
| Преподаватели, кружки, вузы | Курсы, автопроверка домашек, антиплагиат, ведомости |
| Компании | Приватные контесты и хакатоны, тестовые задания |

## Правила проекта

1. **Бэкенд, системный код и инфраструктуру пишешь сам.** ИИ объясняет, подсказывает, ревьюит и советует, что почитать. Готовый код — только если прямо попросил.
2. **Фронтенд пишет ИИ.** Твоя часть — API, которое фронтенд вызывает.
3. **Каждая веха заканчивается демо для живых людей**, а не «инфра готова».
4. **Микросервисы в монорепе с первого дня.** У каждого сервиса своя база, свой контракт и свой деплой; в `pkg/` лежит только платформенный код без доменной логики. Чтобы соло-разработка не утонула в накладных расходах, есть шаблон сервиса, общий каркас и один compose на всё.
5. **Новая технология — только под задачу из роадмапа**, а не потому что модно.
6. **Решения — в [ADR](adr/README.md), выученное — в [журнал](journal/README.md).**

## Чего не делаем

- **GraphQL и BFF.** Браузер вызывает Connect-API через gateway сгенерированным клиентом.
- **Общую базу для нескольких сервисов.** Чужие данные — только через API или события.
- **Биллинг и тарифы**, пока нет внешних пользователей.
- **Свою систему контроля версий.** Git остаётся протоколом, своим будет только git-сервер.
- **Мобильное приложение.**

## Что поменялось относительно первого плана

Первый план назывался CodeSpirit и смотрел на проект как на SaaS. Теперь в центре учёба, отсюда изменения:

| Было | Стало | Почему |
| --- | --- | --- |
| Модульный core, сервисы выносятся постепенно | Микросервисы в монорепе с вехи 0 | Цель — научиться именно микросервисной архитектуре: границы, сеть, события, отказы |
| Kubernetes и Argo CD в первой фазе | Сначала VPS и docker compose, Kubernetes — веха 5 | Быстрее дойти до работающего продукта и не утонуть в инфраструктуре |
| Ory Kratos для входа | Своя авторизация, совместимая с Kratos ([ADR-0002](adr/0002-own-auth.md)) | Понять пароли, сессии и OAuth изнутри и не закрыть путь на Ory |
| GraphQL BFF | Connect напрямую из браузера | Меньше слоёв, которые не учат ничему нового |
| Рейтинг на Python | Рейтинг на Go | Python появляется только в вехе ML |
| Проверка домашек только через git | Отдельная веха «Задания в формате ШАД» | Проверка кода тестами — самостоятельный продукт: отправить можно и файлами, и через git |
| Next.js как часть стека для изучения | Фронтенд пишет ИИ | Цель — всё, кроме фронтенда |

## Рынок и язык

Решено в [#1](https://github.com/nervan-iwnl/Epoch/issues/1).

- **Рынок — весь мир:** СНГ, Европа, США и дальше.
  - Персональные данные (email, пароль, IP) хранит только identity. Остальные сервисы знают `user_id` и публичный ник. Если понадобится хранить данные россиян в РФ (152-ФЗ, ст. 18, ч. 5), это затронет только identity.
  - Минимум GDPR делаем: политика конфиденциальности и удаление аккаунта. При удалении identity стирает персональные данные и публикует событие, остальные сервисы обезличивают свои записи.
- **Язык — английский первым.**
  - Интерфейс и условия задач — на английском. Русский добавим позже, пока рано. Строки интерфейса сразу через i18n, без текста в коде.
  - Ошибки API — только на английском и с кодом, по коду фронтенд покажет перевод.
